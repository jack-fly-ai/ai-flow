# Viewer invariants

The viewer is the only network surface; these invariants keep it safe and correct:

- **Write-time re-validation, not locks.** Every mutating route (`reviewRun` / `stopRun` / `messageRun` / `deleteRun`) re-checks the run status *inside* `withStateUpdate`, because the pre-check and the write are separated by request-body parsing — a concurrent Stop or a second approve click may have moved the state. Losing the race surfaces as a `StateConflictError` → 409, never a clobber. A spawn failure after a recorded review/rework rolls that record back so the run stays consistent.
- **Tenancy by 404, not 403.** Another tenant's run returns 404 (never 403, never a `list`) so existence does not leak across the isolation boundary. A corrupted run record degrades to a 500 "corrupted, use reset" message and must never crash the viewer process (`handle` is unawaited).
- **Package download is bound to the run and tenant.** `sendPackage` resolves the tarball path and requires it to live under the caller's tenant delivery dir (`prefix + path.sep`) *and* match `^<id>_\d{12}\.tar\.gz$`, so a hand-edited `state.json` mirror cannot be pointed at an arbitrary local file.
- **Startup liveness is probed, not assumed.** `createRun` writes the spawned pipeline's pgid to `start-<id>.pgid` and, while polling for `state.json`, short-circuits to a *real* error as soon as that pid is dead (state.json is only written after preflight passes, so "no file yet" is ambiguous). Window: 5s with no recorded pid, up to 30s while the recorded pid is verifiably alive.
- **Gate 4 is recorded after the response.** `reviewRun` approves, replies 200, then fire-and-forgets `progressSetGateAsync` so the slow external `task-progress` tool (120s timeout) never blocks the event loop or other in-flight requests.
- **The live log degrades, it never lies.** `LiveLogPanel` streams the active stage over SSE and treats a *persistent* stream failure (three consecutive `EventSource` errors, or one 401 probe) as a hard fact: the stream is closed and the panel falls back to the 2s polling path with a visible notice, so a broken token or dead stream endpoint can never leave a silently stale panel. A single transient error is tolerated (EventSource reconnects on its own). The fallback state is keyed by `runId` — derived, not stored per stage — so switching runs gets a fresh stream attempt with no state-in-effect.

The live-log stream formatter (`src/agents/streamFormat.ts`) keeps a **strictly append-only** `events` array; tool rows are updated in place via numeric indices stored in `pendingTools`, and filtering happens once, in `finish()`. Do not `splice` / `delete` / `reorder` an element — any positional mutation silently corrupts the tool rows.
