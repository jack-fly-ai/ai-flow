# Isolation edition

`src/auth/auth.ts` adds optional per-tenant access for a shared machine. `auth.tokens` in `ai-flow.config.json` maps a bearer token to a tenant id; every run record carries the owner (`RunState.owner`, stamped by `runPipeline` from `AI_FLOW_TOKEN` — the viewer spawns the CLI with the caller's token, a direct CLI run needs it exported). A user identity sees and can act on its own runs only (the viewer answers 404, never 403, for another tenant's run — existence must not leak); `auth.operator` names the tenant that sees every run (including legacy ownerless records) and is the only identity that may Manage MCP. Token matching is constant-time (sha256 + `timingSafeEqual`). Without an `auth` block (and no `ui.token`) nothing changes: one implicit local-operator identity, no filtering. The legacy `ui.token` stays valid as an operator credential.

Two shared roots are scoped per tenant: the workspace registry (`~/.task-dev-workspaces/<tenant>`) and the delivery directory (`~/task/<tenant>`). `runPipeline` exports both as `TASK_WORKSPACE_REGISTRY` / `TASK_PACKAGE_DIR` for the whole pipeline process (restored in its `finally`), so the task-dev tools, packaging, the phase-4 `~/task` artifacts and the viewer's deliverable lookup are all scoped without further plumbing; the viewer computes the same scope per request via `registryDirFor` / `packageDirFor`, and package downloads are bound to the caller's tenant directory.

The run lock (`src/state/lock.ts`) records the pipeline's uid. A live pid whose recorded uid belongs to ANOTHER user is refused (unless `force`): signal 0 returns EPERM for it, which a boolean liveness check would misread as "dead" and reap — double-booking the workspace. `processExists` distinguishes ESRCH (gone) from EPERM (foreign). A cross-tenant resume through the CLI is refused in `runPipeline` itself — EXCEPT for the operator identity, which may resume any tenant's run (the viewer's Retry/Reject/escalation-answer spawn the pipeline with the caller's token, so refusing the operator would make those actions dead buttons); such a resume keeps the record's original owner and scopes the registry/package env to that owner. Tests: `test/tenancy.test.ts`.
